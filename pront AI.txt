# MISSION : Système de Recommandation IA — SmartHeart

Tu vas implémenter le module complet de recommandation IA intégrée
pour l'application SmartHeart, une plateforme algérienne de
nutrition intelligente ciblant les diabétiques, les cœliaques et
les personnes en quête d'alimentation saine (région Annaba, Algérie).

---

## STACK TECHNIQUE

- Backend : Next.js 14 (App Router) + API Routes (TypeScript)
- Base de données : Supabase (PostgreSQL)
  - Extension pgvector (embeddings 384 dimensions)
  - Extension PostGIS (géolocalisation)
  - Extension unaccent (recherche FTS français)
- Embeddings : Xenova/all-MiniLM-L6-v2 via @xenova/transformers
  (modèle local, pas d'API externe payante)
- Frontend : React + TypeScript
- Client Supabase : @supabase/supabase-js v2

## SCHÉMA EXISTANT (résumé des tables importantes)

### public.profiles
- id UUID (lié à auth.users)
- role: 'user' | 'nutritionist' | 'partner_admin' | 'admin'

### public.user_health_profiles
- user_id UUID → profiles.id
- age, weight_kg, height_cm
- activity_level: 'sedentary' | 'moderate' | 'active'
- health_conditions: text[]
  Valeurs possibles: 'diabetic' | 'celiac' | 'healthy' |
                     'vegetarian' | 'vegan' | 'keto'
- goals: text[]
  Valeurs possibles: 'manage_diabetes' | 'lose_weight' |
                     'avoid_allergens' | 'maintain_weight'
- bmr_kcal, tdee_kcal (métabolisme calculé)
- is_complete: boolean

### public.products
- id, name, brand, description, barcode
- category_id → product_categories.id
- nutri_score: 'A'|'B'|'C'|'D'|'E'
- glycemic_index: 0–100
- labels: text[]  ex: ['bio','sans_gluten','halal']
- compatible_with: text[]  ex: ['diabetic','celiac','vegetarian']
- energy_kcal, carbs_g, sugars_g, fat_g, saturated_fat_g,
  fiber_g, protein_g, sodium_g (pour 100g)
- embedding: vector(384)  ← À REMPLIR par le système IA
- search_vector: tsvector  ← déjà généré (FTS français)

### public.recipes
- id, title, description, image_url
- prep_time_min, cook_time_min, difficulty: 'easy'|'medium'|'hard'
- calories_kcal, price_estimate (en DZD)
- diet_tags: text[]  ex: ['faible_ig','sans_gluten','eco']
- compatible_with: text[]
- embedding: vector(384)  ← À REMPLIR

### public.recipe_ingredients
- recipe_id, product_id (nullable), name, quantity, sort_order

### public.partners (commerces)
- id, name, city, address_line
- latitude, longitude  (+ colonne geom GEOGRAPHY à ajouter)
- opening_hours: JSONB
- is_active, is_verified

### public.partner_inventory
- partner_id, product_id
- price (DZD), quantity, is_available
- low_stock_threshold

### public.user_saved_products — (user_id, product_id)
### public.user_saved_recipes  — (user_id, recipe_id)
### public.product_search_logs — partner_id, product_id, search_term

## CE QUE TU DOIS CONSTRUIRE

### PARTIE 1 — Migrations SQL complémentaires

Crée le fichier `supabase/migrations/001_ai_recommendation.sql` :

1. Activer les extensions manquantes :
   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   CREATE EXTENSION IF NOT EXISTS postgis;
   CREATE EXTENSION IF NOT EXISTS unaccent;
   ```

2. Ajouter les colonnes manquantes sur `products` :
   ```sql
   ALTER TABLE public.products
     ADD COLUMN IF NOT EXISTS embedding vector(384),
     ADD COLUMN IF NOT EXISTS gi_level text
       GENERATED ALWAYS AS (
         CASE
           WHEN glycemic_index IS NULL THEN NULL
           WHEN glycemic_index <= 54   THEN 'faible'
           WHEN glycemic_index <= 69   THEN 'moyen'
           ELSE 'eleve'
         END
       ) STORED,
     ADD COLUMN IF NOT EXISTS search_vector tsvector
       GENERATED ALWAYS AS (
         to_tsvector('french',
           COALESCE(name,'') || ' ' ||
           COALESCE(brand,'') || ' ' ||
           COALESCE(description,''))
       ) STORED;

   CREATE INDEX IF NOT EXISTS idx_products_embedding
     ON public.products USING hnsw(embedding vector_cosine_ops);
   CREATE INDEX IF NOT EXISTS idx_products_fts
     ON public.products USING gin(search_vector);
   CREATE INDEX IF NOT EXISTS idx_products_gi_level
     ON public.products(gi_level);
   ```

3. Ajouter `embedding` sur `recipes` + index HNSW :
   ```sql
   ALTER TABLE public.recipes
     ADD COLUMN IF NOT EXISTS embedding vector(384);
   CREATE INDEX IF NOT EXISTS idx_recipes_embedding
     ON public.recipes USING hnsw(embedding vector_cosine_ops);
   ```

4. Ajouter colonne `geom` PostGIS sur `partners` :
   ```sql
   ALTER TABLE public.partners
     ADD COLUMN IF NOT EXISTS geom geography(POINT, 4326)
       GENERATED ALWAYS AS (
         CASE WHEN latitude IS NOT NULL AND longitude IS NOT NULL
           THEN ST_MakePoint(longitude::float, latitude::float)::geography
           ELSE NULL
         END
       ) STORED;
   CREATE INDEX IF NOT EXISTS idx_partners_geom
     ON public.partners USING gist(geom);
   ```

5. Créer la table `public.notifications` :
   ```sql
   CREATE TABLE IF NOT EXISTS public.notifications (
     id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     user_id     UUID NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
     type        TEXT NOT NULL CHECK (type IN (
                   'stock_alert','new_recipe','badge','tip','recommendation')),
     title       TEXT NOT NULL,
     message     TEXT,
     is_read     BOOLEAN NOT NULL DEFAULT FALSE,
     action_url  TEXT,
     metadata    JSONB DEFAULT '{}',
     created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
   );
   ALTER TABLE public.notifications ENABLE ROW LEVEL SECURITY;
   CREATE POLICY "notif_own_read" ON public.notifications
     FOR SELECT USING (auth.uid() = user_id);
   CREATE POLICY "notif_own_update" ON public.notifications
     FOR UPDATE USING (auth.uid() = user_id);
   CREATE INDEX idx_notif_unread
     ON public.notifications(user_id) WHERE is_read = FALSE;
   ```

6. Créer la fonction SQL `get_nearby_partners` (PostGIS) :
   ```sql
   CREATE OR REPLACE FUNCTION public.get_nearby_partners(
     lat DOUBLE PRECISION,
     lon DOUBLE PRECISION,
     radius_m INT DEFAULT 5000
   )
   RETURNS TABLE (
     partner_id    UUID,
     name          TEXT,
     distance_m    FLOAT,
     distance_km   NUMERIC,
     in_stock_count BIGINT,
     opening_hours JSONB
   )
   LANGUAGE sql STABLE AS $$
     SELECT
       p.id, p.name,
       ST_Distance(p.geom, ST_MakePoint(lon, lat)::geography) AS distance_m,
       ROUND(ST_Distance(p.geom, ST_MakePoint(lon, lat)::geography)/1000.0, 2),
       COUNT(pi.id) FILTER (WHERE pi.is_available = TRUE),
       p.opening_hours
     FROM public.partners p
     LEFT JOIN public.partner_inventory pi ON pi.partner_id = p.id
     WHERE p.is_active = TRUE
       AND ST_DWithin(p.geom, ST_MakePoint(lon, lat)::geography, radius_m)
     GROUP BY p.id
     ORDER BY distance_m ASC;
   $$;
   ```

7. Créer la fonction SQL `get_personalized_products` :
   ```sql
   CREATE OR REPLACE FUNCTION public.get_personalized_products(
     p_user_id UUID,
     p_limit   INT DEFAULT 20
   )
   RETURNS TABLE (
     product_id     UUID,
     name           TEXT,
     brand          TEXT,
     nutri_score    CHAR,
     gi_level       TEXT,
     glycemic_index SMALLINT,
     is_available   BOOLEAN,
     min_price      NUMERIC,
     relevance_score INT
   )
   LANGUAGE plpgsql STABLE AS $$
   DECLARE
     v_conditions text[];
     v_goals      text[];
   BEGIN
     SELECT health_conditions, goals
     INTO v_conditions, v_goals
     FROM public.user_health_profiles
     WHERE user_id = p_user_id AND is_complete = TRUE;

     RETURN QUERY
     SELECT
       p.id, p.name, p.brand, p.nutri_score, p.gi_level,
       p.glycemic_index,
       BOOL_OR(pi.is_available),
       MIN(pi.price),
       (
         CASE WHEN 'diabetic'   = ANY(v_conditions)
                   AND 'diabetic' = ANY(p.compatible_with)    THEN 35 ELSE 0 END +
         CASE WHEN 'celiac'     = ANY(v_conditions)
                   AND 'celiac' = ANY(p.compatible_with)      THEN 35 ELSE 0 END +
         CASE WHEN 'vegetarian' = ANY(v_conditions)
                   AND 'vegetarian' = ANY(p.compatible_with)  THEN 20 ELSE 0 END +
         CASE WHEN p.nutri_score IN ('A','B')                 THEN 20 ELSE 0 END +
         CASE WHEN p.glycemic_index IS NOT NULL
                   AND p.glycemic_index <= 54                 THEN 15 ELSE 0 END +
         CASE WHEN 'lose_weight'  = ANY(v_goals)
                   AND p.energy_kcal < 200                    THEN 10 ELSE 0 END +
         CASE WHEN 'bio' = ANY(p.labels)                      THEN  5 ELSE 0 END
       )::INT AS relevance_score
     FROM public.products p
     LEFT JOIN public.partner_inventory pi ON pi.product_id = p.id
     WHERE p.is_published = TRUE
       AND p.id NOT IN (
         SELECT product_id FROM public.user_saved_products
         WHERE user_id = p_user_id
       )
       AND (
         NOT ('celiac' = ANY(v_conditions))
         OR 'sans_gluten' = ANY(p.labels)
         OR 'celiac' = ANY(p.compatible_with)
       )
     GROUP BY p.id, p.name, p.brand, p.nutri_score,
              p.gi_level, p.glycemic_index,
              p.energy_kcal, p.labels, p.compatible_with
     ORDER BY relevance_score DESC, p.nutri_score ASC
     LIMIT p_limit;
   END;
   $$;
   ```

### PARTIE 2 — Script de génération des embeddings

Crée `scripts/generate-embeddings.ts` :

Ce script charge le modèle Xenova/all-MiniLM-L6-v2 localement,
génère les embeddings pour tous les produits et recettes sans
embedding, et les upsert dans Supabase.

```typescript
// scripts/generate-embeddings.ts
import { createClient } from '@supabase/supabase-js'
import { pipeline } from '@xenova/transformers'

const supabase = createClient(
  process.env.SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!  // service role pour bypasser RLS
)

async function buildProductText(product: any): string {
  // Construire un texte riche pour l'embedding
  const parts = [
    product.name,
    product.brand ?? '',
    product.description ?? '',
    `Nutriscore ${product.nutri_score ?? ''}`,
    product.glycemic_index ? `IG ${product.glycemic_index}` : '',
    (product.labels ?? []).join(' '),
    (product.compatible_with ?? []).join(' '),
    product.gi_level ? `indice glycémique ${product.gi_level}` : '',
  ]
  return parts.filter(Boolean).join('. ')
}

async function main() {
  const embedder = await pipeline(
    'feature-extraction',
    'Xenova/all-MiniLM-L6-v2'
  )

  // ── Produits sans embedding ──────────────────────────────
  const { data: products } = await supabase
    .from('products')
    .select('id, name, brand, description, nutri_score, glycemic_index, labels, compatible_with, gi_level')
    .is('embedding', null)
    .eq('is_published', true)

  console.log(`📦 ${products?.length ?? 0} produits à encoder...`)

  for (const product of products ?? []) {
    const text = await buildProductText(product)
    const output = await embedder(text, { pooling: 'mean', normalize: true })
    const embedding = Array.from(output.data) as number[]

    await supabase
      .from('products')
      .update({ embedding })
      .eq('id', product.id)

    console.log(`✅ ${product.name}`)
  }

  // ── Recettes sans embedding ──────────────────────────────
  const { data: recipes } = await supabase
    .from('recipes')
    .select('id, title, description, diet_tags, compatible_with, difficulty')
    .is('embedding', null)
    .eq('is_published', true)

  console.log(`🍽️  ${recipes?.length ?? 0} recettes à encoder...`)

  for (const recipe of recipes ?? []) {
    const text = [
      recipe.title,
      recipe.description ?? '',
      (recipe.diet_tags ?? []).join(' '),
      (recipe.compatible_with ?? []).join(' '),
      `difficulté ${recipe.difficulty}`
    ].filter(Boolean).join('. ')

    const output = await embedder(text, { pooling: 'mean', normalize: true })
    const embedding = Array.from(output.data) as number[]

    await supabase
      .from('recipes')
      .update({ embedding })
      .eq('id', recipe.id)

    console.log(`✅ ${recipe.title}`)
  }

  console.log('🎉 Embeddings générés avec succès.')
}

main().catch(console.error)
```

Ajoute dans `package.json` :
```json
"scripts": {
  "embed": "ts-node scripts/generate-embeddings.ts"
}
```

## CONTRAINTES ET RÈGLES IMPORTANTES

1. **Pas de clé API OpenAI / Cohere / Anthropic** — uniquement le
   modèle local Xenova/all-MiniLM-L6-v2 (gratuit, tourne côté
   serveur Next.js ou dans un script local)

2. **Filtre dur cœliaque** : si `health_conditions` contient 'celiac',
   NE JAMAIS recommander un produit qui ne contient pas 'sans_gluten'
   dans ses labels ET ne contient pas 'celiac' dans compatible_with

3. **Filtre dur diabétique** : ne jamais scorer comme "Compatible"
   un produit avec glycemic_index > 69

4. **Langue** : toute l'interface est en français. Les messages
   d'erreur, états vides, et tooltips aussi.

5. **Currency** : prix toujours en DA (Dinar Algérien), formaté
   avec `Intl.NumberFormat('fr-DZ', { style: 'currency', currency: 'DZD' })`
   → affichage : "320 DA"

6. **Géolocalisation** : coordonnées par défaut si non disponibles =
   Centre Annaba : lat: 36.9001, lon: 7.7662

7. **Performance** :
   - Memoïser les embeddings générés (ne pas regénérer si déjà présents)
   - Utiliser `content-visibility: auto` sur les listes de cards
   - Les appels Supabase dans les API routes doivent avoir un timeout de 5s

8. **TypeScript strict** : pas de `any`, interfaces pour toutes
   les réponses API, types Supabase générés depuis `supabase gen types`

## TEST DE VALIDATION ATTENDU

Après implémentation, ces scénarios doivent fonctionner :

- Un user avec `health_conditions: ['diabetic']` → 0 produit
  avec gi_level 'eleve' dans ses recommandations
- Un user avec `health_conditions: ['celiac']` → 0 produit
  sans label 'sans_gluten' dans ses recommandations
- `GET /api/recommendations/products?limit=10` retourne 200 avec
  `profile_applied: true` si le wizard est complété
- `GET /api/stores/nearby?lat=36.90&lon=7.77` retourne les 5
  commerces Annaba triés par distance
- `GET /api/recommendations/similar?product_id=xxx` retourne
  6 produits similaires avec similarity score > 0.3
Ce prompt couvre 100% du système IA de SmartHeart : migrations SQL, génération d'embeddings locaux avec Xenova (sans coût API), 5 routes API, 2 composants React complets avec le design system SmartHeart, un webhook pour les nouveaux produits, et les règles métier strictes pour les profils diabétiques et cœliaques.
